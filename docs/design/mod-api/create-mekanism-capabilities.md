# Create and Mekanism capabilities

Clean-room capability audit of main `5c2583c030` (2026-11-08); no foreign mod or NeoForge source consulted. Status applies to the stated engine operation, not a completed port. Tests below were inspected, not run here. Public wiki requirements are unversioned unless noted; exact release applicability remains unknown. Create's [official CurseForge description](https://www.curseforge.com/minecraft/mc-mods/create) (listing 6.0.10 for Minecraft 1.21.1) establishes animated automation, but no detailed interaction contract. The Create manual and Fandom Deployer page were inaccessible; detailed moving-structure requirements come from [#794](https://github.com/arismoko/horizon/issues/794), and fake-player interactions are the audit scope requested by #806, not a claimed Create contract.

Source abbreviations: [items](https://wiki.aidancbrady.com/wiki/Logistical_Transporter), [fluids](https://wiki.aidancbrady.com/wiki/Mechanical_Pipe) (v9 upgrade note), [energy](https://wiki.aidancbrady.com/wiki/Universal_Cable) (V10 upgrade note), [chemicals](https://wiki.aidancbrady.com/wiki/Pressurized_Tube), [sides](https://wiki.aidancbrady.com/wiki/Machine_Configuration) are official Mekanism user wiki pages. They motivate operations, not engine implementation details.

## Verified gap

| Expected versus observed | Reproducible missing call and natural receiver | Issue/design |
|---|---|---|
| Assemble two blocks, retaining block-entity contents and one ticking owner; translate/rotate, save and synchronize that owner. Main exposes no assembly operation or structure handle; ordinary entity capability providers cannot perform that ownership transfer. | Place two machine blocks at (0,64,0)/(1,64,0). A mod needs `level.assemble_structure(host, cells, pivot)` returning a proposed `StructureRef`, then `structure.set_transform(host, transform)`. Neither entry point exists. Proposed API belongs on `LevelRef` for assembly and the returned structure handle for motion; atomic ownership transfer must be engine-owned. | Existing [#794](https://github.com/arismoko/horizon/issues/794); [design PR #2310](https://github.com/arismoko/horizon/pull/2310), intended page `concepts/moving-structures.md` once landed. These are proposed names pending that design, not current API. |

## Route limits

Works rows establish exactly the listed operation. Game tests use an in-process host (some set dedicated options), not a running network acceptance scene. LAN, integrated-server scheduling, actual dedicated networking and wasm execution were not verified for these rows. Item/entity lookup implementations were traced through provider dispatch; no claim is made that every provider journals correctly. API `wire_resources.rs:18–30` explicitly refuses erased capabilities across link groups; this audit does not establish typed provider interoperability across all native/wasm groups. Chemical identity policy remains the provider's responsibility.

No hook count or complete-port claim follows from these results. Board searches used `gh issue list -R arismoko/horizon --state all --search` with `energy`, `fake player`, and `moving structures`; the verified carrier gap maps to #794. No issues were filed and no additional gap is inferred from untested routes.
