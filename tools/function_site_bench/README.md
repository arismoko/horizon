# Function-site measurement preparation

These scripts prepare measurement-only variants of the external points-tick kit. They do not change the production point machinery. No game data or external kit code is committed here.

The kit must be read before execution and copied privately to `target/wholegame/kit`. Use base `980f0459eb767ddc1c9c6592988e2cbfd4dc51f5` in `target/wholegame/kit-source`, the kit's B staging output at `target/wholegame/kit-out/stage-B`, and a private Rust 1.97.1 toolchain. Set an explicit, separate `CARGO_TARGET_DIR` for every variant: the Dyna environment otherwise defaults it to the checkout's `target`.

- `make_mitigations.py` writes independent macro patches for the small-leaf rule, non-atomic startup flag read, borrowed cold arguments, and their combination. These are experimental, not a supported mod loader. The startup read requires no concurrent writes to eligibility flags; existing sealed-registration semantics permit this only after startup. The borrowed variant uses temporary `Option` slots to transfer ownership safely through a closure whose captures are references.
- `prepare_api.py` copies B into E and keeps only API-capable functions. It adds one shared flag per function, initialized after registry seal from that function's head/return subscription bits. It does not expose raw dispatch in the expansion. This is an unmodded benchmark variant, not a complete removal of internals registration APIs.
- `prepare_pointer.py` transplants the `no-points` replacement stager onto the kit's fixed base, then runs the original points stager with A's no-points macro. It expects the transplanted helper binary at `target/wholegame/pointer-gen-target/release/fnr-stage` and the original no-points worktree at `target/wholegame/C-source`. The helper consists of that branch's `source.rs` and `replace.rs`, added to the fixed-base generator, and a binary calling `replace::stage`. Lower-crate targets are restricted to targets discoverable in the fixed-base B metadata.
- `run-on-host.sh` is the reviewed host-side driver. It copies a private bundle into `~/bench-fnr`, pins to Intel `cpu_core` logical CPUs, runs five rotating tick-only rounds, invokes the kit's summary and census scripts, preserves results and the common generated save, and removes copied build/resource trees. Subsequent variant campaigns must set `FNR_SAVE` to the initial saved world. It does not install packages, use sudo, or access the network.

Measurements and limitations live in the room's `fn-replace/wholegame.md` note. No performance result is implied by preparing or compiling a variant.
