# Function-site measurement preparation

These scripts prepare measurement-only variants of the external points-tick kit. They do not change the production point machinery. No game data or external kit code is committed here.

The kit must be read before execution and copied privately to `target/wholegame/kit`. Use base `980f0459eb767ddc1c9c6592988e2cbfd4dc51f5` in `target/wholegame/kit-source`, the kit's B staging output at `target/wholegame/kit-out/stage-B`, and a private Rust 1.97.1 toolchain. Set an explicit, separate `CARGO_TARGET_DIR` for every variant: the Dyna environment otherwise defaults it to the checkout's `target`. When staging beneath the existing checkout, run `git init -q` in the disposable staged tree before applying the kit's git-format patches. Otherwise `git apply` can report success while skipping every path because it inherits the outer repository's subdirectory prefix. Assert that zc_bench.rs, both timing calls, COUNTS, and the intended variant expansion actually exist before building.

- `make_mitigations.py` writes independent macro patches for the small-leaf rule, non-atomic startup flag read, borrowed cold arguments, and their combination. These are experimental, not a supported mod loader. The startup read requires no concurrent writes to eligibility flags; existing sealed-registration semantics permit this only after startup. The borrowed variant uses temporary `Option` slots to transfer ownership safely through a closure whose captures are references.
- `prepare_shared_api.py` builds E from the fixed-base B source using Option C's shared-cell stager and point expansion pinned to `no-points-api-points` head `11091819d7`. A function's entry loads its replacement cell once; listened dispatch is installed into that cell after registry seal. `api_filter.rs` removes raw-only or non-replaceable point attributes before that pass. It expects the helper binary at `target/wholegame/pointer-api-gen-target/release/fnr-api-stage` and the pinned expansion at `target/wholegame/api-reference-point.rs`. The fixed-base API records and catalog remain unchanged for comparability; this benchmark is not a complete loader/API migration. The earlier independent-flag E0 was never built and is not in the campaign.
- `prepare_pointer.py` transplants the `no-points` replacement stager onto B's fixed-base staged source, then applies A's no-points macro. It temporarily reverses instrumentation before staging replacements, so measurement helpers gain no sites, and keeps B's point metadata intact rather than accidentally listing generated installers as new points. It expects the transplanted helper binary at `target/wholegame/pointer-gen-target/release/fnr-stage` and the original no-points worktree at `target/wholegame/C-source`. The helper consists of that branch's `source.rs` and `replace.rs`, added to the fixed-base generator, and a binary calling `replace::stage`. Lower-crate targets are restricted to targets discoverable in the fixed-base B metadata.
- `run-on-host.sh` is the reviewed host-side driver. It copies a private bundle into `~/bench-fnr`, pins to four Ryzen physical cores and their SMT siblings, runs five rotating tick-only rounds, invokes the kit's summary and census scripts, preserves results and the common generated save, and removes copied build/resource trees. Subsequent variant campaigns must set `FNR_SAVE` to the initial saved world. It does not install packages, use sudo, or access the network. Its separately prepared perf and two libraries come only from signed Arch packages extracted privately; the driver scopes their library paths to perf, records package provenance, and records actual perf invocations. A busy Dyna CI worker aborts before the campaign.

Measurements and limitations live in the room's `fn-replace/wholegame.md` note. No performance result is implied by preparing or compiling a variant.
